Куди класти фото корпусів
==========================

Кожен корпус має свою теку. Кладіть файли туди — будь-якою кількістю,
з будь-якою назвою, аби розширення було підтримуване:

  photos/admin/     — адміністративний корпус
  photos/lab/        — лабораторний корпус
  photos/tech/       — технологічний корпус
  photos/dorm/       — гуртожиток
  photos/college-1.* — ОДНЕ фото коледжу для головної сторінки
                       (саме такою назвою, розширення будь-яке з нижченаведених)

Підтримувані розширення: .jpg, .jpeg, .png, .webp (великі/малі літери —
байдуже). Усе інше (текстові файли, .gif, .bmp тощо) ігнорується.

Автопідхоплення не потребує PHP — працює на чистому JavaScript,
у два рівні:

1. Якщо є photos-manifest.json (його оновлює GitHub Actions при пуші,
   якщо сайт на GitHub Pages) — сайт бере список фото звідти.
2. Якщо його немає (наприклад, на сервері коледжу, куди файли просто
   копіюють без GitHub) — сайт сам відкриває теку кожного корпусу
   (photos/admin/ тощо) і читає список файлів прямо зі сторінки
   автоіндексу, яку віддає сервер. Це і дозволяє знаходити файли
   з будь-якою назвою, а не лише пронумеровані за шаблоном.

   Важливо: рівень 2 спрацює, лише якщо на сервері увімкнено перегляд
   вмісту теки (autoindex/directory listing). Для Apache це вже
   налаштовано файлом .htaccess у цій же теці (нічого додатково
   робити не треба). Якщо сервер на Nginx — попросіть, хто його
   адмініструє, додати "autoindex on;" для шляху /photos/, файл
   .htaccess на Nginx не діє.

В обох випадках результат однаковий: додали файл — з'явився, видалили
— зник. Нічого в data.js редагувати не потрібно.

Якщо з якоїсь причини не спрацював жоден варіант (наприклад, і немає
photos-manifest.json, і directory listing вимкнено) — автоматика
вимикається, але сайт не ламається. Тоді потрібно вручну вписати
шляхи у поле photos кожного корпусу в data.js, наприклад:

  photos: ["photos/admin/foto1.jpg", "photos/admin/foto2.jpg"]

Порожній масив photos: [] (як зараз) означає "показати заглушку".
Один файл — фото без каруселі. Два і більше — автоматично з'являються
стрілки та крапки навігації.

Рекомендації до самих файлів:
- Орієнтація: горизонтальна чи вертикальна — підійде: блок сам
  підлаштовує висоту, а зображення заповнює її з обрізкою країв
  (object-fit: cover), тому найважливіше тримайте ближче до центру кадру
- Розмір: досить 1600 px по довшій стороні — більше лише збільшить
  вагу сторінки без помітної різниці в якості
- Вага файлу: бажано до ~400–600 КБ на фото
